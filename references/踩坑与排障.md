# DOCX 踩坑与排障手册

本文件是 `docx-writer` 的**深度排障参考**。SKILL.md 里放结论，这里放根因、判据和修法。
每条都是真实踩过的，附「现象 → 根因 → 修法 → 判据」。

---

## 一、结构类

### 1. `kids[i]` ≠ 段落索引（头号坑）

**现象**：目录域结构坏，Word 报 `TablesOfContents.Count = 0`，21 条目录全显示「错误!未定义书签。」；
或 '目录' 标题段整段丢失、「目录」两字被塞进第一条条目。

**根因**：`body` 的直接子元素除 `w:p` 还有 `w:tbl` 和 `w:sectPr`。第一个表之后，
`list(body)[i]` 与"第 i 段"完全错位。按"段号"取素材必然取错 —— 连锁后果：
H1/H2 原型互换、外层 `TOC` 域 begin 组被复制到每条条目（`TOC \o` 出现 22 次）、目录节 `sectPr` 丢失。

**修法**：摘任何原型之前先跑勘察脚本，用输出核对索引：

```bash
python scripts/dump_body_kids.py 运维手册模板.docx --runs 18 19 20 21
```

**判据**：构建产物的 `TOC \o` 计数 == 1；`fldCharType begin` 计数 == `end` 计数。

---

### 2. 剥离外层 TOC 域时多剥了一个 run

**现象**：构建断言报「域字符不配平 begin=15 end=17」——每条条目少一个 begin、多一个 end。

**根因**：外层 `TOC` 域的三个 run（`fldChar begin` / `instrText TOC…` / `fldChar separate`）
挂在**首条条目段**上，紧跟着的就是该条目自己的 `HYPERLINK begin`。
写成"扫到域就收"的循环会把 `HYPERLINK begin` 一并剥掉。

**修法**：只剥**三段**，逐段校验内容：

```python
# r[0] 必须 fldCharType=begin
# r[1] 必须 instrText 以 'TOC' 开头
# r[2] 必须 fldCharType=separate
# 任一段不符 → 整体放弃剥离，返回原样
```

**判据**：`begin` 与 `end` 计数相等，且 `TOC \o` 唯一。

---

### 3. body 级 `sectPr` 不能摘

**现象**：清空正文重建后，页面设置（A4 / 页边距）全部丢失。

**根因**：`body` **末尾**的 `sectPr` 是 body 级节属性，不是段落里的。
清空循环若把它一起 `remove`，整篇文档失去页面设置。

**修法**：清空时显式放过它，最后再 `append` 回去：

```python
SECT = kids[-1] if tag(kids[-1]) == 'sectPr' else None
for ch in kids:
    if ch is not SECT:
        body.remove(ch)
...
body.append(SECT)
```

---

### 4. 在分节符附近插段落会把分节符顶走

**现象**：封面与目录被并进同一节，封面分节符跑到整份目录之后。

**根因**：`doc_insert_paragraph_with_text(idx=X)` 的语义是「插在**结束于 X 的段落之后**」。
若 X 正好是**承载 `sectPr` 的载体段**，新段会插到载体**前面**，节边界跟着漂移。

**修法**：凡在分节符附近插入过，必须回读节属性复核；必要时离线搬运：

```python
ppr.remove(sectPr)          # 从错误载体段摘掉
target_ppr.append(sectPr)   # 挂到正确的末尾段
```

**判据**：`section_count` 与各节 `range` 符合预期。

---

### 5. 模板把 `numPr` 写进 heading **样式**里 → 目录出现重复编号

**现象**：目录条目渲染成「1、1、项目概况」。

**根因**：`heading 1` 样式自带 `numPr`（样式级编号），段落上又挂了一个 `numPr`（段落级）。
两个编号叠加。

**判据**：查 `styles.xml` 里 `heading N` 有没有 `pPr/numPr`；
再查正文标题段落有没有段落级 `numPr`。**两者都有就是叠加**。

**修法**：二选一——要么去掉段落级，要么去掉样式级。

---

### 6. 章标题编号出现两次（内容表侧）

**现象**：内容表里写 `('H1', '1、运维概述')`，渲染成「1、1、运维概述」。

**根因**：基底 `numbering.xml` 的 H1 定义是 `%1、`，会自动输出编号，文本里再写一遍就重了。

**修法**：H1 文本**不写编号**（`build_docx.py` 会打印提醒）。
H2/H3 不使用自动编号，编号**要**写进文本。

---

### 7. 以模板为基底后，模板自带的 header/footer 变成孤儿部件

**现象**：文档能打开，但页眉页脚消失或残留模板文案。

**根因**：换基底后 `sectPr` 里的 `headerReference r:id` 指向的关系还在，但内容可能被替换/清空。

**修法**：Phase B 改 zip 时**同步改页眉文案**，并核对 `[Content_Types].xml`
与 `word/_rels/document.xml.rels` 里的 header/footer 条目是否齐全。

🚨 **最阴的变体**：自建 header/footer 时，一个"清理未引用部件"的循环会把**刚加进去的**
`Content_Types` Override 又删掉 —— 结果是 Word 报「文件可能已经损坏」。
写清理循环时，务必把**本轮新增的部件名**加进白名单。

---

### 8. Word 报「文件可能已经损坏」的二分定位法

一轮见效：把候选嫌疑部件（header / footer / numbering / settings / styles）
逐个替换回**基底的原始字节**，重新打包打开。哪一步恢复正常，问题就在那一个部件。
比盲读 XML 快一个数量级。

### 9. 插目录的幂等：**别用 `w:rsidR` 标记**

**现象**：第二次运行目录插入脚本，Word 报 `TablesOfContents 数 = 2`，文档里出现两份目录。

**根因**：把 `w:rsidR="00A0C001"` 当作"本工具插入的节点"标记，重跑时按标记剔除。
但 **Word COM 打开并保存时会把 rsid 重写掉**，标记全部失效 → 旧目录没被剔除 → 插进第二份。

**修法**：改用 Word **一定会保留**的特征识别旧目录，可靠判据（三者之一）：

| 判据 | 说明 |
| --- | --- |
| 文本 == 「目录」标题 | 归一化空格后比较 |
| 样式是 `toc 1` / `toc 2` / `toc 3` | 按 `w:name` 反查得到 styleId |
| 含域字符且**文本为空** | 外层 TOC 域 `end` 的载体段（Word 会把它单独成段） |

**从正文起点向前回溯**收集，遇到第一个不符合判据的段落就停。这样对"Word 重排过目录"的文档同样有效。

### 10. 别「从 TOC begin 向后找第一个 `fldChar end`」

**现象**：删除旧目录只删掉 2 段，其余目录段残留 → 域字符不配平（实测 `begin=8 end=9`）。

**根因**：Word 更新目录后，**首条条目段内部就带了条目自己（HYPERLINK / PAGEREF）的 `fldChar end`**。
"向后找第一个 end" 会把它当成外层 TOC 域的结尾，删除范围只覆盖到第 2 段。
（真正的外层域 `end` 被 Word 移到了**最后一条条目之后的独立空段**里。）

**判据**：dump 出来看首条条目段的 fldChar 序列形如
`begin,separate,begin,separate,end`（外层 TOC 的 begin+separate，加条目自己的 begin+separate+end），
而末尾另有一个只有 `end`、没有文本的段。

**修法**：按段落特征向前回溯（见上条），或按**域嵌套深度**计数（`begin` +1 / `end` −1，归零处才是外层 `end`）。

### 11. 目录插入/重建脚本：校验必须放在写盘**之前**

**现象**：脚本断言失败（域字符不配平），但文件已经被改写成双目录状态，得手工回滚。

**根因**：`save_parts()` 写在 `assert` 之前。

**修法**：先把 XML 组装到内存 → 做完全部断言 → **再**写盘。
这样断言失败时磁盘上的文件保持原样。实测这一改动让"③ 幂等失败"那一轮没有污染测试文档。

## 二、格式类

### 9. lxml 元素复用 → 封面空段"塌陷"、整页上移

**现象**：封面比模板上移 62pt，空段消失。

**根因**：lxml 元素**只能有一个父节点**。同一个 `rPr`/`pPr` 对象挂到第二个段落上时，
会从第一个段落被"搬走" —— 前一段丢失属性、后一段看似正常。

**修法**：凡是可能挂到多个父节点的元素，**每次新建**（写成函数或 `deepcopy`）。

```python
# ✗ 复用
rpr = build_rpr(size=36)
p1.append(rpr); p2.append(rpr)      # p1 的 rpr 被搬走！
# ✓ 每次新建
p1.append(build_rpr(size=36)); p2.append(build_rpr(size=36))
```

---

### 10. 🚨 Word 保存会**悄悄删掉**标题的段前/段后

**现象**：构建脚本明明写了 `before=340 after=330`，Word 打开再保存后变成 0，
标题贴上页眉（PDF 实测：模板标题顶距页眉 46.4pt，成品只有 28.2pt）。

**根因**：模板的 `w:spacing` 带了四个伴随属性
`beforeLines="0" beforeAutospacing="0" afterLines="0" afterAutospacing="0"`，
我们只写 `before/after`，Word 把它们当**冗余属性**整组清掉（同批被清的还有各种显式 0 值）。

**修法**：`build_ppr(sp_lines=True)`（默认已开）——`before/after` 必须与四属性同行写。

**判据**：改完用 **PDF 实测**标题距页眉的间距，不要只看 XML。
受控实验确认：模板原样 / 模板补四属性 / 我们的产物，各让 Word 打开保存，差别只在这四个属性。

---

### 11. 页眉缺斜体

**现象**：页眉文案对了，但没斜体，与模板不一致。

**根因**：模板 `header1.xml` 的 run 带 `<w:i/><w:iCs/>`，替换文本时若整体重建 run 会丢。

**修法**：只改 `w:t` 的文本，不动 `rPr`；或替换后检查 `w:i` 是否还在。

---

### 12. 修订记录表字号偏小

**现象**：修订表看起来比模板小。

**根因**：模板表体单元格**不写显式 `sz`**，靠样式继承，脚本 dump 出来的"字号"是表头的。

**修法**：按模板实测设 `hdr=18`(9pt) / `body=21`(10.5pt)；核验用 **PDF span 实测**，不要用 XML dump。
（本项目曾因只看 XML 误判为"表体也是 9pt"。）

---

### 13. 题注与图片的先后顺序

**规律**：**表题在表上、图题在图下**。
表题带 `keepNext`（与表同页）；图题放最后，不带 `keepNext`。

---

### 14. 写单元格丢失字体（空 run + 带格式 run）

**现象**：写入文字后字体/字号全丢。

**根因**：模板单元格常见结构是 `run0 = 空 run（无 rPr）` + `run1 = 带新宋体/10.5 的真实文字`。
若写进 run0 并删掉其余 run，就整体丢格式。

**修法**：定位到**最后一个文字非空的 run** 再写入，删除其余 run：

```python
target = None
for r in runs:
    if r.text.strip():
        target = r
if target is None:
    target = runs[-1]
for r in runs:
    if r is not target:
        r._element.getparent().remove(r._element)
target.text = text
```

---

### 15. 纵向合并单元格会被整格覆盖

写合并单元格（`vMerge`）时，覆盖会波及整个纵向合并区。
处理前先查 `tcPr/vMerge`，跳过 continuation 单元格（只有 `w:val="continue"` 的）。

---

### 16. 模板「表」样式从 `table of figures` 继承左缩进 → 表题整体右偏

查表样式的 `basedOn` 链；必要时给表题段显式 `ind left=0`。

## 三、插图类

### 17. 🚨 图片被固定行距裁掉（最隐蔽）

**现象**：`document.xml` 里 `w:drawing`、`r:embed`、`word/media/*.png` **全部齐备**，
但打印/导出后完全看不见（被压成 20 磅高）。

**根因**：图片段继承了正文的 `lineRule="exact" line="400"`（固定 20 磅行距）。

**修法**：图片段必须显式写 **`line="240" lineRule="auto"`**（单倍）。

**判据**：导出 PDF 前后**总页数**对比（本项目首次 15 页图全丢，修好后 17 页）。
页数没变就要怀疑图没占位。**唯一可靠的复核是渲染成 PNG 用 Read 看图**。

> 本技能的 `build_figure()` 已强制 `lineRule="auto"`，并在 `_verify()` 里断言
> 所有含 `w:drawing` 的段落都不是 `exact` 行距。

### 18. 插图的三件套缺一不可

| 部件 | 位置 | 缺了会怎样 |
|---|---|---|
| 图片二进制 | `word/media/imageN.png` | 图片位置空白 |
| 关系条目 | `word/_rels/document.xml.rels` | Word 报「内容有问题」 |
| Content Type | `[Content_Types].xml` 的 `<Default Extension="png" .../>` | Word 报「内容有问题」 |

本技能的 `add_image_part()` 三件一起做，并在 `_verify()` 里断言三者数量一致。

### 19. `doc_insert_image` 的 idx 落在哪一段很关键

传 `idx = 段落 end` 会把图片**塞进那一整段文字里**，并给该段套上居中/单倍行距（正文文字跟着变形）。
必须传 `段落 end + 1`，或新建一个空段用 `空段 range.begin + 1`。改完一定回读 `w:drawing` 落在哪个段落。

### 20. 自绘图必做「文字溢出/重叠」自动化自检

模型看不了图，靠肉眼之外的唯一办法是**几何自检**：

```python
fig.canvas.draw()
r = fig.canvas.get_renderer()
inv = ax.transData.inverted()
for t in texts:
    bb = t.get_window_extent(renderer=r)
    (x0, y0), (x1, y1) = inv.transform([[bb.x0, bb.y0], [bb.x1, bb.y1]])
    box = getattr(t, '_box', None)
    if box:
        bx, by, bw, bh = box
        assert x0 >= bx - .004 and x1 <= bx + bw + .004 \
           and y0 >= by - .004 and y1 <= by + bh + .004, ('文字溢出框', t.get_text())
```

- **量测必须用 `TextPath`，不要用 `get_window_extent` + `canvas.draw()`** ——
  后者每量一次就渲染整个画布，6 张图实测直接跑成 `SIGTERM`。
- 排版口诀：先按「框宽 × 字号」估算每行放几个汉字（1 汉字 ≈ 字号 pt，1 ASCII ≈ 0.5 字号 pt），
  **宁可把详细说明搬到图外的表格里，图上只留 4~8 字的短标签**。
- 出图**自绘优于 AI 生图**：技术架构/流程图里的中文标注用图像生成模型会糊字。
- `figsize=(5.73, H)`（A4 正文可用宽 5.73in）、`dpi=220`；中文字体用
  `FontProperties(fname=r'C:/Windows/Fonts/simhei.ttf')`（**宋体是 `simsun.ttc`**，写 `.ttf` 会 `FileNotFoundError`）。
- SimHei 缺失字形：`▾ ⌄ ‹ › ⚠ ✓` → 换 `v` / `< 1 2 3 >` / `!` / `√`。
- `Polygon` 顶点要 `zip` 成 (N,2)；箭头用 `FancyArrowPatch(arrowstyle='-|>', mutation_scale=8)`，
  别手写 head 长度（会被 `mutation_scale` 再放大）。

### 21. 别为了凑版面造图

界面长什么样 → **复用截图**；流程/架构/关系 → 可自绘。
「要尽量多写」时**先想表格，再想自绘图** —— 表格是零风险的高密度载体，自绘图每张都要人肉核对。
实战教训：给原型设计自绘 14 张线框，用户一句「不要画图，就直接复用截图」全部作废。

## 四、公式类

### 22. 🚨 `compatibilityMode=11` 让 Word 把 OMML 降级成 VML 图片

**现象**：构建产物 `m:oMath` 数正确、XML 全过；但用 Word COM 打开并保存后，
`m:oMath` 变成 **0**，公式被改写成 `<w:pict><v:shape equationxml="…">` + `QUOTE` 域的老式图片公式，
PDF 里再也抽不到公式文字。

**根因**：模板 `settings.xml` 里 `compatibilityMode = 11`（Word 2003 兼容模式），
该模式不使用 OMML 公式模型（12 = Word 2007，**15 = Word 2013+**）。

**修法**：构建 Phase B 把 `compatibilityMode` 改成 `15`。

**验收口径（必须这样查）**：① 打开 **COM 保存后**的 docx，`<m:oMath` 计数 == 期望；
② `<w:pict` 计数 == 0；③ 导出 PDF 里有大量 **CambriaMath** 字体的 span。
**只看构建产物查不出来**，必须 COM 之后再查一遍。

### 23. 最佳路径：pandoc

```bash
pandoc formulas.tex -o formulas.docx      # 本机：C:\ProgramData\Anaconda3\Scripts\pandoc.EXE
```

一条命令把 LaTeX 数学转成 OMML，无需 TeX 发行版。注入时**必须包一层带命名空间声明的根节点**，
否则 lxml 报 `Namespace prefix m on oMath is not defined`：

```python
wrap = '<root xmlns:m="%s" xmlns:w="%s">%s</root>' % (M_URI, W_URI, cached_xml)
p.append(etree.fromstring(wrap.encode('utf-8'))[0])
```

### 24. 公式段的行距**绝对不能**是 `exact`

正文用「固定值 20 磅」时，带分式/根式/上下标的公式会被裁切。
公式段改 `line="400" lineRule="auto"`。
段落 `pPr/rPr` 的 `ascii` 设成 **`Cambria Math`**，让 `oMath` 继承数学字体。

### 25. 行内公式的高度必须 < 正文行高

行内公式只放**矮结构**：单字母、上下标（`y_i`）、带帽（`\hat{y}`）、带横线（`\bar{y}`）、
`\mu_x`、`[0,1]`。需要 `\frac` / `\sqrt` / 带上下限的 `\sum` / 矩阵 → **提到 display 公式段**。
实测安全值：39 条行内片段渲染高度 max 17.44pt < 20pt。

### 26. Python 普通字符串里 `\t` / `\b` 会被转义

`'\theta'` 得到的是 `制表符 + heta`，`'\bar{y}'` 得到 `退格 + ar{y}` —— pandoc 收到控制字符，
转换结果必然错，**且在 JSON/日志里看不见**。
**含 `\t`/`\b`/`\n`/`\f`/`\r` 开头的 LaTeX 一律用原始字符串** `r'\theta'`。
自检：`assert not any(ord(c) < 32 for c in s)`。

### 27. 下划线式标识符不是数学符号

`e_id`、`n_level`、`t_start` 这类是**数据库字段名**，不是 `y_i` 那种数学变量。
判定：出现在「字段说明表/数据字典」里的是字段名，出现在公式推导、模型说明里的是数学符号。**只改后者**。

## 五、COM 相关

### 28. COM 保存后的核验语义（严格断言必然误报）

Word 保存会做一轮规范化，**按新语义解读**：

| 变化 | 影响 | 应对 |
|---|---|---|
| styleId 重编号（`heading1 2→1`、`TableGrid 11→a6`、`toc1 7→TOC1`） | 断言按数字 id 全红 | 按 `w:name` 反查样式 |
| 表格边框从 `tblPr` 移入 `Table Grid` 样式 | 断言"`tblPr` 里没边框"误报 | 查样式定义或看 PDF 实绘线，**效果等价** |
| 等于默认值的属性被归一化删掉 | 断言"四伴随属性缺失"误报 | 只看 `before/after` 在不在，降为 INFO |
| `updateFields` 被抹 | 别断言它还在 | 目录已刷过就等于完成使命 |
| 拆 SDT、重排 rels | 结构断言变化 | 按语义而非字面断言 |

### 29. `WinError 5 拒绝访问`

WPS/Word 开着目标文件时写盘会失败。
**不要**用「临时文件 + `os.replace`」——直接 `zipfile.ZipFile(path, 'w')` 按原部件顺序覆盖写。
COM 导 PDF 前先 `shutil.copy2` 到临时路径再导。

### 30. 目录页码的两遍编译 vs COM 更新

手工两遍编译（占位 → 导 PDF 读页脚 → 回填）容易出错：要跳过目录页，
且 H1 渲染为 `1、项目概况`（无空格）而目录条目习惯写 `1、 项目概况`（有空格），检索串要分开定义。
**优先用 COM 的 `TablesOfContents(1).Update()`**，让 Word 自己算。

## 六、验收方法

### 31. 「模板 PDF 基准」比对法（强烈推荐）

不要凭肉眼或凭样式定义推断。**渲染模板 PDF，用 PyMuPDF 取 span 的 x/y/字号逐行比对**。
本项目「封面整体上移 62pt」「修订表表体字号」两个问题都是靠这个基准定位的。
基准文件建议放 `.workbuddy/preview/_模板基准_<模板名>.pdf`，同项目可复用。

### 32. PDF 越界的两类虚警（别误判）

| 虚警 | 原因 | 判据 |
|---|---|---|
| 行末标点越界约一个全角 | 中文标点悬挂（正常排版） | 右边界容差放宽 **1 个 em**；模板 PDF 亦如此 |
| 斜体数学字母 bbox 外扩、相邻 span 重叠 0.6~6.3pt | 斜体倾斜 + 组合字符（`\hat` 的帽子抽成独立 `^` span） | 重叠量小且涉及斜体/`^` 即正常；真重叠 >8pt 且伴随文字截断 |
| 行内公式末尾窄空格 span 溢出右边距 2~9pt | 无墨迹 | **只把「非空格 span 越界」当问题** |

### 33. 目录抽样取"最后一次出现"

目录条目是 `1、 运维概述`（带空格）、正文标题是 `1、运维概述`（无空格）。
抽样核对字号时要去空格归一化并**取末次出现**，否则会命中目录页造成虚警。

### 34. 渲染成 PNG 用 Read 看图（最有价值的最后一步）

自动化断言只能覆盖可量化的部分。封面、目录、正文页渲染成 PNG 目视一遍，
能抓住"断言全绿但就是不对"的问题。
